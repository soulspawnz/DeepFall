# Deepfall browser validation

Use for repeated verification of the local Deepfall game after UI, sprite, campaign or SID changes.

## Contract

Deliverable: reproducible browser checks and screenshots, with actual failures reported. Preserve the user's live browser session and unrelated processes. Engine simulation, headless browser checks and live in-app interaction must be reported separately. Do not claim automated attempts are human completions.

## Workflow

1. Read the changed modules and run appropriate Node tests through `I:\Nexus\Cortex\run.cmd -x node`.
2. Confirm the task-owned preview serves HTTP 200 on port 8767. Restart only its exact owned Node PID if the allowlist changed; use hidden startup. Never terminate unrelated processes.
3. Run `test/original-media-browser.mjs` with the installed Playwright module path, installed Chromium executable path and screenshot output directory. This verifies atlas palette, real AudioWorklet output, both SID models and errors.
   For sound hanging on pause/death or state themes, also run `test/audio-lifecycle.test.mjs` and `test/audio-lifecycle-browser.mjs` (same browser arguments). Measure AC energy at native output, not just the worklet meter; a constant SID DAC offset is not an audible held tone. Original effects must drain even when `scene.active` is false, while ambience/countdown sources stop. Pause intentionally plays its SID theme when MUSIC is on; with MUSIC off it must stay silent through sound toggles and chip changes. Death's original effect precedes the short lament, which must end without a sustained tone. Hidden tabs stay silent and restart restores gameplay audio.
4. Run `test/original-browser.mjs` for campaign, layout or control changes. Use `test/sid-browser.mjs` for Deepfall soundtrack changes. Browser scripts take the same three arguments. These checks use a separate headless browser.
5. Run `test/replay-browser.mjs` when replay UI changes, and `test/playtest-replays.test.mjs` when engine rules change. Regenerate the 300 attempts only when rule/solver changes invalidate them.
   For live recording changes, run `test/live-replays.test.mjs`. Verify the library keeps historical screenshot-only results, exact saved live-input recordings, and the automated archive distinct. Never invent a replay for a run whose inputs were not recorded. Preserve an active cave by opening a separate validation tab instead of reloading it. Existing Windows test dependencies may be under `C:/Users/soulspawn/AppData/Local/npm-cache/_npx/*/node_modules/playwright/index.mjs`; locate an installed copy before searching larger trees.
   For the learning player, run `test/learning-player.test.mjs` and `test/learning-browser.mjs`. The latter takes the same browser dependency/output arguments. Verify an actual learned-policy improvement against a cold evaluation, save/reload equivalence, route variety, real exits in saved AI traces, cancellation on cave changes, worker stop, and separation from live keyboard recordings. Random routes alone do not establish learning; a diamond quota alone does not establish a win. Benchmarks and browser checks are simulated tests, not live keyboard play.
   Replay-history changes must retain every completed training attempt, baseline and evaluation independently of bounded learning memory. Verify IndexedDB persistence, a failed/attempt-limit replay, chronological playlist controls, and export. Recovery of older simulated runs requires matching every stored fingerprint and result; mark recovered traces explicitly. Keep accelerated browser playlist tests bounded: use engine replay checks for every trace and focused browser checks for playlist behavior instead of rendering many minutes of canvas frames.
   For library/import changes, run `test/learning-library.test.mjs` and `test/learning-library-browser.mjs`. Check persistent collapse, 10/25/50/100 page sizes, sorting, combined filters, empty pages, model cave matching, replay outcome/fingerprint verification, atomic rejection, deduplication and persistence. Test input files only in an isolated browser; never replace the user's stored learning for validation. Verify legacy models/replays remain usable after policy upgrades and report actual before/after performance, including plateaus. Changing routes alone is not progress.
   The learning card has **Overview / Graphs / Replays / Data** tabs. Select Replays before clicking saved runs, Graphs before interacting with charts, and Data before imports/exports. The Overview's full report is collapsed: expand it before asserting visible `innerText` (read-only `textContent` supports background progress waits). Test tab arrow/Home/End navigation, single visible panel, cross-view live status/STOP, and mobile layout. Row buttons display **PLAY** with descriptive accessible names. Playwright `waitForFunction` takes timeout options as its third argument (`null, {timeout:120000}`), not its second; otherwise training checks retain the 30-second default.
   For planning changes, also run `test/route-planner.test.mjs`. Preserve existing value-table entries when enabling planning; retain partial input traces, unfinished branches and visited fingerprints across save/reload. Seed from the existing archive and re-simulate every prefix from birth; never revive a dead snapshot. Back up the current user model and archive with `tab.playwright.waitForEvent('download')` registered **before** clicking export, then use the returned download path. Do not mistake an older file with the same base name for the current export. Compare all original records after merging new traces. Model-based evaluation may follow a known winning memory; distinguish that from discovering a new route. Use `tools/train-planner.mjs` for a bounded local continuation, with private backup paths and output paths supplied by the caller. Never ship the user's exported model or input traces as tracked fixtures. For a repeated partial-result plateau, inspect remaining diamond supply as well as collected count: a high-diamond route may already have destroyed enough resources to be unwinnable. Count pending diamond blasts, exempt regenerating amoeba/magic-wall worlds, and version explored-state fingerprints when changing expansion rules so old expansions do not suppress new alternatives. Confirm an improved run through exact engine replay; route diversity alone is insufficient.
   In-app training validation must observe actual candidate movement on the canvas with **Render training in game** enabled (the default). Run `test/training-preview-browser.mjs` to verify input animation, chosen-run completion, saved attempts, stop, and restoration of the paused manual cave including its timer. Candidate routes may rewind to an exact cloned common-prefix checkpoint; label search branches separately from a continuous attempt or saved replay. Hidden tabs must not block worker acknowledgements. Uncheck the preview in unrelated background-training browser tests. Planner yields are already throttled (decisions 1, 9, 17, ...); forward these `frontier` updates rather than filtering them again with `decision % 8 === 0`. Keep the distinction between new exploratory attempts, their recorded playback and the retained winning evaluation explicit.
   Planning arrows must use actual simulated player coordinates, not raw directional inputs (pushes and blocked moves can leave the player still). Verify the bounded branch sample shares the expanded candidate's origin, coordinates are adjacent, the legend distinguishes the recent route / candidate-endpoint forecasts / fatal forecasts, and **SHOW BRANCHES** can hide the overlay while training continues. These local options are not the entire frontier. Draw Rockford above the lines and keep the arrows out of normal play and saved replay rendering.
   **Show search rewinds** defaults off and persists separately from learning. In smooth mode, the canvas waits during search and then plays a completed recording continuously; verify monotonically increasing consumed-input ticks within an attempt, accurate planning/playback labels, and exact equality of learned inputs/outcomes with search-preview mode. Enable the toggle explicitly when testing candidate switches or branch arrows. It is disabled during a job or when in-game rendering is off. Distinguish visual search resets from actual Echo gameplay rewinds. WATCH NEXT ATTEMPT must not play the same completed recording a second time after an enabled preview already displayed it.
   Generation planning changes require `test/generation-planning.test.mjs`: verify outlet clearing before magic feed, actual rock-to-diamond conversion and harvest, expired-wall exclusion, idle-versus-expired search keys, and amoeba diamond conversion versus rock conversion. Candidate setup scores must not count as collected gems or wins. Keep explored-state namespaces versioned without resetting model values or archived inputs. Observe bounded G/H trials in the app and report actual limits, not only success on a synthetic fixture. Offline solver changes also require `test/offline-solvers.test.mjs`; imports must not execute a CLI, output directories must be explicit, existing results must not be overwritten, and every saved win must replay exactly.
   Learned scoring multipliers require `test/priority-learning.test.mjs` and `test/priority-learning-browser.mjs`. Verify actual ranking changes, bounded deterministic profile proposals, outcome-based retention/rejection, fixed feasibility constraints, exclusion of evaluation from updates, old-model preservation, strict import validation, exact recorded weights/quality, and save/reload equivalence. Observe a reference trial and changed-weight trials in the app. Back up and compare all old replay objects and decision keys after the live test. Separate progress from an actual exit, and do not attribute all improvement to weights when retained routes and search continuation also changed.
   Learning graph changes require `test/learning-progress.test.mjs` and `test/learning-progress-browser.mjs`. Use synthetic histories longer than 100 training runs, mixed with repeated winning evaluations. Verify full-archive counts, training-only rolling rates, failure exclusion from escape speed, exact numeric axes, range/filter independence, baseline/evaluation markers, keyboard inspection, selected-run playback, cave isolation and readable mobile SVG axes. Keep the user's active cave intact when opening the updated graphs. Do not treat a quota line or a winning evaluation as a new training escape.
   Automatic exploration changes require `test/adaptive-exploration.test.mjs` and `test/adaptive-exploration-browser.mjs`. Verify the five-attempt review cadence, 10–60% bounds, fresh progress versus plateau/regression, successful-run speed, exclusion of evaluations, per-cave controller save/reload and fixed manual overrides. Check the percentage on actual saved training records, not only the explanatory label. Distinguish the active attempt's setting from the idle preview for the next attempt; preserve existing learned values and replay inputs.
   Timer changes require `test/trapped-timer.test.mjs`: distinguish permanent entrapment from idling, legal random pushes, snap collection, temporary gravity/enemy blocks and possible world changes. Preserve grace state in Echo snapshots. Record timer-rule flags on new traces and run legacy traces with their recorded rules; never silently invalidate the replay archive. Preserve an active paused run when loading UI updates would discard it.
   For fullscreen changes, run `test/fullscreen-browser.mjs` to check native entry, F exit, a 4:3 stage, mobile viewport fallback, touch controls and Escape exit. An optional fourth argument overrides the base URL for a hosted-site check. Verify relative sprite, replay and worklet URLs when deploying under a project subpath such as `/DeepFall/`.
6. Review a screenshot of the active game, and report tested outcomes and limits. The in-app browser must be controlled through its provided runtime; if unavailable, say so and offer the visible replay control.
