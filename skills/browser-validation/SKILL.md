# Deepfall browser validation

Use for repeated verification of the local Deepfall game after UI, sprite, campaign or SID changes.

## Contract

Deliverable: reproducible browser checks and screenshots, with actual failures reported. Preserve the user's live browser session and unrelated processes. Engine simulation, headless browser checks and live in-app interaction must be reported separately. Do not claim automated attempts are human completions.

## Workflow

1. Read the changed modules and run appropriate Node tests through `I:\Nexus\Cortex\run.cmd -x node`.
2. Confirm the task-owned preview serves HTTP 200 on port 8767. Restart only its exact owned Node PID if the allowlist changed; use hidden startup. Never terminate unrelated processes.
3. Run `test/original-media-browser.mjs` with the installed Playwright module path, installed Chromium executable path and screenshot output directory. This verifies atlas palette, real AudioWorklet output, both SID models and errors.
   For sound hanging on pause/death or state themes, also run `test/audio-lifecycle.test.mjs` and `test/audio-lifecycle-browser.mjs` (same browser arguments). Measure AC energy at native output, not just the worklet meter; a constant SID DAC offset is not an audible held tone. Original effects must drain even when `scene.active` is false, while ambience/countdown sources stop. Pause intentionally plays its SID theme when MUSIC is on; with MUSIC off it must stay silent through sound toggles and chip changes. Death's original effect precedes the short lament, which must end without a sustained tone. Hidden tabs stay silent and restart restores gameplay audio.
4. Run `test/original-browser.mjs` for campaign, layout or control changes. Use `test/sid-browser.mjs` for Deepfall soundtrack changes. Browser scripts take the same three arguments. These checks use a separate headless browser.
5. Run `test/replay-browser.mjs` when replay UI changes, and `test/playtest-replays.test.mjs` when engine rules change. Regenerate the 300 attempts only when rule/solver changes invalidate them.
   For live recording changes, run `test/live-replays.test.mjs`. Verify the library keeps historical screenshot-only results, exact saved live-input recordings, and the automated archive distinct. Never invent a replay for a run whose inputs were not recorded. Preserve an active cave by opening a separate validation tab instead of reloading it. Existing Windows test dependencies may be under `C:/Users/soulspawn/AppData/Local/npm-cache/_npx/*/node_modules/playwright/index.mjs`; locate an installed copy before searching larger trees.
   For the learning player, run `test/learning-player.test.mjs` and `test/learning-browser.mjs`. The latter takes the same browser dependency/output arguments. Verify an actual learned-policy improvement against a cold evaluation, save/reload equivalence, route variety, real exits in saved AI traces, cancellation on cave changes, worker stop, and separation from live keyboard recordings. Random routes alone do not establish learning; a diamond quota alone does not establish a win. Benchmarks and browser checks are simulated tests, not live keyboard play.
   Replay-history changes must retain every completed training attempt, baseline and evaluation independently of bounded learning memory. Verify IndexedDB persistence, a failed/attempt-limit replay, chronological playlist controls, and export. Recovery of older simulated runs requires matching every stored fingerprint and result; mark recovered traces explicitly. Keep accelerated browser playlist tests bounded: use engine replay checks for every trace and focused browser checks for playlist behavior instead of rendering many minutes of canvas frames.
   For library/import changes, run `test/learning-library.test.mjs` and `test/learning-library-browser.mjs`. Check persistent collapse, 10/25/50/100 page sizes, sorting, combined filters, empty pages, model cave matching, replay outcome/fingerprint verification, atomic rejection, deduplication and persistence. Test input files only in an isolated browser; never replace the user's stored learning for validation. Verify legacy models/replays remain usable after policy upgrades and report actual before/after performance, including plateaus. Changing routes alone is not progress.
   The learning card groups progress, training and replay history. Imports/exports are inside the initially closed **Backups & data** disclosure; open it before testing those buttons. The full report is also collapsed: expand it before asserting visible `innerText` (read-only `textContent` still supports background progress waits). Row buttons display **PLAY** while retaining descriptive accessible names. STOP replaces TRAIN during a worker job. Playwright `waitForFunction` takes timeout options as its third argument (`null, {timeout:120000}`), not its second; otherwise training checks silently retain the 30-second default.
   For planning changes, also run `test/route-planner.test.mjs`. Preserve existing value-table entries when enabling planning; retain partial input traces, unfinished branches and visited fingerprints across save/reload. Seed from the existing archive and re-simulate every prefix from birth; never revive a dead snapshot. Back up the current user model and archive with `tab.playwright.waitForEvent('download')` registered **before** clicking export, then use the returned download path. Do not mistake an older file with the same base name for the current export. Compare all original records after merging new traces. Model-based evaluation may follow a known winning memory; distinguish that from discovering a new route. Use `tools/train-planner.mjs` for a bounded local continuation, with private backup paths and output paths supplied by the caller. Never ship the user's exported model or input traces as tracked fixtures.
   Timer changes require `test/trapped-timer.test.mjs`: distinguish permanent entrapment from idling, legal random pushes, snap collection, temporary gravity/enemy blocks and possible world changes. Preserve grace state in Echo snapshots. Record timer-rule flags on new traces and run legacy traces with their recorded rules; never silently invalidate the replay archive. Preserve an active paused run when loading UI updates would discard it.
   For fullscreen changes, run `test/fullscreen-browser.mjs` to check native entry, F exit, a 4:3 stage, mobile viewport fallback, touch controls and Escape exit. An optional fourth argument overrides the base URL for a hosted-site check. Verify relative sprite, replay and worklet URLs when deploying under a project subpath such as `/DeepFall/`.
6. Review a screenshot of the active game, and report tested outcomes and limits. The in-app browser must be controlled through its provided runtime; if unavailable, say so and offer the visible replay control.
